Servidor de archivos con Samba

Contexto y objetivo

Con el fin de contar con un servidor de archivos compatible con macOS, se configuró en MAGINOT un recurso compartido mediante Samba (SMB) sobre Rocky Linux 10.1.

La elección de Samba se debe a que macOS se conecta de forma nativa mediante smb://, lo que permite acceder fácilmente a carpetas compartidas desde Finder.

En este caso, se configuró la carpeta:

/srv/bishop

como un recurso privado para el usuario stoich.

Alcance de la configuración

  • Sistema operativo del servidor: Rocky Linux 10.1

  • Protocolo de compartición: SMB/Samba

  • Carpeta compartida: /srv/bishop

  • Usuario autorizado: stoich

  • Cliente principal: macOS

  • Acceso previsto: red local o mediante mecanismos internos de red

Preparación de la carpeta compartida

Primero se verificó que la carpeta existiera dentro de /srv/ y se definió como propiedad exclusiva del usuario stoich.

Establecer propietario

sudo chown -R stoich:stoich /srv/bishop

Restringir permisos

Para evitar acceso de otros usuarios del sistema, se dejaron permisos privados:

sudo chmod 700 /srv/bishop sudo find /srv/bishop -type d -exec chmod 700 {} \; sudo find /srv/bishop -type f -exec chmod 600 {} \;

Con ello:

  • los directorios quedan con permisos 700

  • los archivos quedan con permisos 600

Instalación de Samba

Se instaló Samba y las utilerías de cliente:

sudo dnf install -y samba samba-client

Configuración de SELinux

Dado que Rocky Linux utiliza SELinux, fue necesario etiquetar la carpeta compartida con el contexto apropiado para Samba.

Instalar semanage si es necesario

sudo dnf install -y policycoreutils-python-utils

Asignar contexto SELinux

sudo semanage fcontext -a -t samba_share_t "/srv/bishop(/.*)?" sudo restorecon -Rv /srv/bishop

Esto permite que Samba pueda acceder a la carpeta sin desactivar SELinux.

Configuración del usuario Samba

Aunque el usuario stoich ya existía en Linux, Samba requiere registrar su propia contraseña.

sudo smbpasswd -a stoich sudo smbpasswd -e stoich

Configuración de /etc/samba/smb.conf

Se utilizó el archivo de configuración por defecto de Rocky Linux y se añadieron únicamente los ajustes necesarios para compatibilidad con macOS y para exponer el recurso bishop.

Archivo de configuración

[global]
        workgroup = SAMBA
        security = user
        vfs objects = fruit streams_xattr

        passdb backend = tdbsam

        printing = cups
        printcap name = cups
        load printers = yes
        cups options = raw

        # Install samba-usershares package for support
        include = /etc/samba/usershares.conf

[homes]
        comment = Home Directories
        valid users = %S, %D%w%S
        browseable = No
        read only = No
        inherit acls = Yes

[printers]
        comment = All Printers
        path = /var/tmp
        printable = Yes
        create mask = 0600
        browseable = No

[print$]
        comment = Printer Drivers
        path = /var/lib/samba/drivers
        write list = printadmin root
        force group = printadmin
        create mask = 0664
        directory mask = 0775

[bishop]
        path = /srv/bishop
        browseable = yes
        read only = no
        guest ok = no
        valid users = stoich
        force user = stoich
        create mask = 0600
        directory mask = 0700

Notas sobre esta configuración

  • vfs objects = fruit streams_xattr mejora la compatibilidad con clientes macOS

  • guest ok = no evita accesos anónimos

  • valid users = stoich restringe el acceso solo al usuario autorizado

  • force user = stoich asegura que las operaciones dentro del recurso se realicen como ese usuario

Validación de la configuración

Antes de iniciar el servicio, se verificó que el archivo no tuviera errores de sintaxis:

sudo testparm

Una salida exitosa indica que la configuración es válida.

Apertura del servicio en el firewall

Para permitir conexiones SMB dentro de la red, se habilitó el servicio Samba en firewalld:

sudo firewall-cmd --permanent --add-service=samba sudo firewall-cmd --reload

Activación de los servicios

Se habilitaron e iniciaron los demonios de Samba:

sudo systemctl enable --now smb nmb

Verificación de estado

systemctl status smb nmb

La salida esperada debe mostrar ambos servicios como:

active (running)

Prueba local en el servidor

Para verificar que el recurso estuviera disponible correctamente, se listaron los recursos Samba desde el propio servidor:

smbclient -L localhost -U stoich

Con ello debe aparecer el recurso compartido bishop.

Conexión desde macOS

Desde Finder, el recurso se puede montar mediante:

Ir → Conectarse al servidor

y utilizar una de las siguientes rutas:

smb://IP_DE_MAGINOT/bishop

o bien:

smb://maginot/bishop

Después se autentica con:

  • usuario: stoich

  • contraseña: la definida con smbpasswd
