Instalación de Slurm para una sola máquina

Configuración de un nodo local con partición ripley, MUNGE y registros en /srv/bishop

Slurm, acrónimo de Simple Linux Utility for Resource Management, es un sistema de administración de trabajos utilizado en servidores de cómputo y clústeres de alto rendimiento.

Su función principal es organizar el uso de los recursos computacionales, como CPUs, memoria y nodos de cómputo. En lugar de que los usuarios ejecuten procesos directamente en el servidor, envían trabajos a una cola. Slurm decide cuándo ejecutarlos, cuántos recursos asignarles y registra información básica sobre su ejecución.

En un clúster grande, Slurm puede administrar muchos nodos. Sin embargo, también puede utilizarse en una sola máquina. Esto es útil cuando se desea controlar el uso de recursos, evitar que un usuario sature el servidor y enseñar buenas prácticas de cómputo reproducible.

Objetivo

El objetivo de este tutorial es instalar y configurar Slurm en un servidor con Rocky Linux 10.1 usando una sola máquina como controlador y nodo de cómputo.

La partición de Slurm se llamará:

ripley

Además, para evitar llenar la partición raíz /, los archivos persistentes de Slurm se almacenarán en:

/srv/bishop/slurm

Esquema general

La instalación tendrá los siguientes componentes:

  • munge: servicio de autenticación usado por Slurm.

  • slurmctld: controlador principal de Slurm.

  • slurmd: daemon que ejecuta trabajos en el nodo de cómputo.

  • slurm.conf: archivo principal de configuración.

  • cgroup.conf: configuración para controlar recursos con cgroups v2.

  • jobcomp/filetxt: registro básico de trabajos terminados.

Información del servidor

Antes de instalar Slurm, es importante conocer las características del servidor.

hostname
hostname -f
cat /etc/os-release
nproc
free -h
df -h
lsblk
getent ahostsv4 maginot

En este caso, el servidor reportó:

Hostname: maginot
Sistema operativo: Rocky Linux 10.1
CPUs: 72
RAM: 251 GiB

También se decidió usar /srv/bishop para almacenar los archivos persistentes de Slurm, ya que la raíz / tiene poco espacio disponible.

Preparar repositorios y dependencias

En Rocky Linux 10.1, Slurm no se encuentra directamente disponible en los repositorios base como paquete listo para instalar. Por ello, se construyeron paquetes RPM a partir del código fuente de Slurm.

Primero se instalan las dependencias necesarias:

sudo dnf update -y
sudo dnf install -y epel-release dnf-plugins-core
sudo dnf config-manager --set-enabled crb

Después:

sudo dnf install -y \
  autoconf automake dbus-devel libbpf-devel make mariadb-devel \
  munge munge-libs munge-devel \
  pam-devel perl-devel perl-ExtUtils-MakeMaker \
  python3 readline-devel rpm-build rpmdevtools wget tar gcc gcc-c++

Construcción de los RPMs de Slurm

Crear el árbol de construcción RPM:

rpmdev-setuptree

Descargar Slurm:

cd ~/rpmbuild/SOURCES
wget https://download.schedmd.com/slurm/slurm-25.05.5.tar.bz2

Construir los paquetes:

rpmbuild -ta ~/rpmbuild/SOURCES/slurm-25.05.5.tar.bz2

Al finalizar, los RPMs quedan en:

~/rpmbuild/RPMS/x86_64/

Los paquetes mínimos necesarios para una instalación de una sola máquina son:

slurm-25.05.5-1.el10.x86_64.rpm
slurm-slurmctld-25.05.5-1.el10.x86_64.rpm
slurm-slurmd-25.05.5-1.el10.x86_64.rpm

Instalación de Slurm

Instalar los RPMs generados:

sudo dnf install -y \
  ~/rpmbuild/RPMS/x86_64/slurm-25.05.5-1.el10.x86_64.rpm \
  ~/rpmbuild/RPMS/x86_64/slurm-slurmctld-25.05.5-1.el10.x86_64.rpm \
  ~/rpmbuild/RPMS/x86_64/slurm-slurmd-25.05.5-1.el10.x86_64.rpm

Crear usuario y grupo de Slurm

Slurm debe ejecutarse con un usuario de sistema dedicado.

sudo groupadd -g 2002 slurm 2>/dev/null || true

sudo useradd -u 2002 -g slurm -c "SLURM Workload Manager" \
  -d /var/lib/slurm -s /sbin/nologin -m slurm 2>/dev/null || true

Verificar:

id slurm

Configurar MUNGE

MUNGE permite autenticar los componentes de Slurm.

Crear la llave:

sudo dd if=/dev/urandom bs=1 count=1024 of=/etc/munge/munge.key
sudo chown munge:munge /etc/munge/munge.key
sudo chmod 0400 /etc/munge/munge.key

Iniciar el servicio:

sudo systemctl enable --now munge
systemctl status munge --no-pager -l

Probar MUNGE:

munge -n | unmunge | head

Si el resultado muestra:

STATUS: Success (0)

MUNGE está funcionando correctamente.

Crear directorios de Slurm en /srv/bishop

Para evitar llenar la partición raíz, los archivos persistentes de Slurm se guardarán en /srv/bishop/slurm.

sudo mkdir -p /srv/bishop/slurm/{log,state,spool/slurmd}
sudo chown -R slurm:slurm /srv/bishop/slurm
sudo chmod -R 755 /srv/bishop/slurm

También crear el directorio de configuración:

sudo mkdir -p /etc/slurm
sudo chown slurm:slurm /etc/slurm

Detectar recursos del servidor

Una vez instalado Slurm, se debe obtener la configuración real del nodo:

slurmd -C

Este comando devuelve una línea similar a:

NodeName=maginot CPUs=72 Boards=1 SocketsPerBoard=... CoresPerSocket=... ThreadsPerCore=... RealMemory=...

Esta línea debe usarse como base para configurar el nodo en slurm.conf.

Crear slurm.conf

Crear el archivo principal de configuración:

sudo tee /etc/slurm/slurm.conf > /dev/null <<'EOF'
ClusterName=maginot
SlurmctldHost=maginot
SlurmUser=slurm
AuthType=auth/munge

StateSaveLocation=/srv/bishop/slurm/state
SlurmdSpoolDir=/srv/bishop/slurm/spool/slurmd

SlurmctldPidFile=/run/slurmctld.pid
SlurmdPidFile=/run/slurmd.pid

SlurmctldLogFile=/srv/bishop/slurm/log/slurmctld.log
SlurmdLogFile=/srv/bishop/slurm/log/slurmd.log

SwitchType=switch/none
MpiDefault=none
ProctrackType=proctrack/cgroup
TaskPlugin=task/cgroup,task/affinity
ReturnToService=2
SchedulerType=sched/backfill
SelectType=select/cons_tres
SelectTypeParameters=CR_Core

JobCompType=jobcomp/filetxt
JobCompLoc=/srv/bishop/slurm/log/job_completions.log

NodeName=maginot CPUs=72 Boards=1 SocketsPerBoard=2 CoresPerSocket=18 ThreadsPerCore=2 RealMemory=257303 State=UNKNOWN
PartitionName=ripley Nodes=maginot Default=YES MaxTime=INFINITE State=UP
EOF

La línea NodeName debe ajustarse con la salida real de:

slurmd -C

Crear cgroup.conf

Rocky Linux 10 usa cgroups v2, por lo que se crea el archivo:

sudo tee /etc/slurm/cgroup.conf > /dev/null <<'EOF'
CgroupPlugin=cgroup/v2
EnableControllers=yes
EOF

Ajustar permisos:

sudo chown slurm:slurm /etc/slurm/slurm.conf /etc/slurm/cgroup.conf
sudo chmod 644 /etc/slurm/slurm.conf /etc/slurm/cgroup.conf
sudo setfacl -m u:slurm:x /srv/bishop

Crear archivos de log

sudo touch /srv/bishop/slurm/log/slurmctld.log
sudo touch /srv/bishop/slurm/log/slurmd.log
sudo touch /srv/bishop/slurm/log/job_completions.log

sudo chown slurm:slurm /srv/bishop/slurm/log/*.log

Iniciar servicios

sudo systemctl enable --now munge
sudo systemctl enable --now slurmctld
sudo systemctl enable --now slurmd

Si ya estaban iniciados:

sudo systemctl restart munge
sudo systemctl restart slurmctld
sudo systemctl restart slurmd

Verificar instalación

Revisar el estado de los servicios:

systemctl status munge --no-pager -l
systemctl status slurmctld --no-pager -l
systemctl status slurmd --no-pager -l

Ver la partición:

sinfo

La salida esperada debe mostrar algo similar a:

PARTITION AVAIL  TIMELIMIT  NODES  STATE NODELIST
ripley*      up   infinite      1   idle maginot

Revisar el nodo:

scontrol show node maginot

Probar ejecución con srun

srun -p ripley -N1 -n1 hostname

La salida esperada es:

maginot

Probar ejecución con sbatch

Crear un script de prueba:

cat > ~/prueba_slurm.sh <<'EOF'
#!/bin/bash
#SBATCH -J prueba
#SBATCH -p ripley
#SBATCH -N 1
#SBATCH -n 1
#SBATCH -c 2

echo "Inicio: $(date)"
echo "Host: $(hostname)"
echo "Job ID: $SLURM_JOB_ID"
echo "CPUs asignadas: $SLURM_CPUS_PER_TASK"

sleep 10

echo "Fin: $(date)"
EOF

Enviar el trabajo:

sbatch ~/prueba_slurm.sh

Ver la cola:

squeue

Revisar la salida:

cat slurm-*.out

Probar encolamiento de trabajos

Para verificar que Slurm administra correctamente los recursos, se pueden enviar más trabajos de los que caben simultáneamente.

Crear script:

cat > ~/test_cola_maginot.sh <<'EOF'
#!/bin/bash
#SBATCH -J cola_maginot
#SBATCH -p ripley
#SBATCH -N 1
#SBATCH -n 1
#SBATCH -c 8
#SBATCH --time=00:05:00

echo "JobID: $SLURM_JOB_ID"
echo "Host: $(hostname)"
echo "Inicio: $(date)"
echo "CPUs asignadas: $SLURM_CPUS_PER_TASK"

sleep 120

echo "Fin: $(date)"
EOF

Enviar 20 trabajos:

for i in {1..20}; do
    sbatch ~/test_cola_maginot.sh
done

Ver la cola:

squeue

También se puede observar en vivo:

watch -n 2 squeue

Salir de watch con:

Ctrl + C

Revisar registros de trabajos completados

Como se configuró:

JobCompType=jobcomp/filetxt
JobCompLoc=/srv/bishop/slurm/log/job_completions.log

los trabajos completados pueden revisarse con:

tail -n 20 /srv/bishop/slurm/log/job_completions.log

Para seguir el registro en vivo:

sudo tail -f /srv/bishop/slurm/log/job_completions.log

Notas sobre sacct

En esta instalación no se configuró slurmdbd, por lo que el comando:

sacct

puede mostrar:

Slurm accounting storage is disabled

Esto no indica un error en la instalación básica. Significa que no se ha configurado el sistema completo de contabilidad de Slurm con base de datos.

Para una instalación inicial en una sola máquina, el registro con jobcomp/filetxt puede ser suficiente.

Comandos útiles para usuarios

Ver particiones disponibles:

sinfo

Ver trabajos en cola:

squeue

Enviar un trabajo:

sbatch script.sh

Cancelar un trabajo:

scancel JOBID

Ejecutar un comando interactivo sencillo:

srun -p ripley -N1 -n1 hostname

Comandos útiles para administración

Reiniciar servicios:

sudo systemctl restart slurmctld
sudo systemctl restart slurmd

Releer configuración:

sudo scontrol reconfigure

Ver estado del nodo:

scontrol show node maginot

Ver logs del controlador:

sudo tail -f /srv/bishop/slurm/log/slurmctld.log

Ver logs del nodo:

sudo tail -f /srv/bishop/slurm/log/slurmd.log

Ver trabajos completados:

sudo tail -f /srv/bishop/slurm/log/job_completions.log

Conclusión

Con esta configuración, Slurm queda funcionando en una sola máquina con Rocky Linux 10.1. Aunque no se trata de un clúster multinodo, esta instalación permite controlar el uso de CPUs, organizar trabajos en cola y registrar ejecuciones.

Este esquema es útil para servidores compartidos de bioinformática, donde distintos usuarios ejecutan análisis que pueden consumir muchos recursos. Al obligar a enviar trabajos mediante Slurm, se reduce el riesgo de saturar el servidor y se promueve una forma más ordenada y reproducible de trabajar.
